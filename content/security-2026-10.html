Security Release

October 2026 CVE Release

Apache Traffic Server 9.2.16, 10.1.5 and 10.2.1 fix the 15 security vulnerabilities listed below. They affect releases up to and including 9.2.15, 10.1.4 and 10.2.0 — among them request-smuggling, memory-safety, and access-control issues, the most serious rated CVSS 10.0. Fixed releases are available now, and all users are strongly encouraged to upgrade promptly.

CVE-2026-111816ImportantCVSS 9.3

A malformed 302 response bypasses parse-error rejection through the Transfer-Encoding: chunked carve-out

Apache Traffic Server forwarded a malformed 302 response that should have been rejected as a parse error, because the Transfer-Encoding: chunked carve-out bypassed the rejection path. A response that two peers can read differently is then stored and served, allowing cache poisoning and response-framing desync.

CVE-2025-31699ImportantCVSS 8.9

Origin connection still owed a request body is reused, enabling request smuggling

Apache Traffic Server can return an origin connection to the shared pool while the origin is still waiting on a request body the client declared but never fully sent, including when the client used Expect: 100-continue. The origin then reads a later request on that connection as leftover body data, which lets an attacker smuggle requests past ATS access controls, disrupt other users' requests, or poison the cache.

Component
HTTP state machine
Type
Request smuggling
Fixed in
9.2.16 / 10.1.5 / 10.2.1
Reported by
Martin van Kervel Smedshammer, Nick Muerdter
CVE-2025-55702ImportantCVSS 8.7

An unread Expect: 100-continue request body is framed as a new request

When a client sends a POST with Expect: 100-continue and the origin answers before reading the body, Apache Traffic Server parses the unread body left on the client connection as the next request. An attacker behind a front-end proxy that shares connections to Traffic Server can use this to smuggle requests past the front end and desynchronize responses for other users.

Component
HTTP/1
Type
Request smuggling
Fixed in
9.2.16 / 10.1.5 / 10.2.1
Reported by
Sebastiano Sartor

CVE-2026-111817ModerateCVSS 5.3

Dropping chunked trailers stalls a passthrough transfer until timeout

Apache Traffic Server can stall a chunked transfer that it passes through with its trailers removed (proxy.config.http.drop_chunked_trailers) until the connection times out, because it waits for the trailer bytes it has already dropped. Trailer dropping is on by default in 10.x. In 9.2.x it is off by default, and those versions are affected only if it is enabled.

Component
HTTP tunnel
Type
Denial of service
Fixed in
10.1.5 / 10.2.1
